## 1. Summary

Reframe the application as a **Meta marketing and growth platform for creators and Shopify merchants**. The primary value proposition is: AI-driven post ideas, trend insights, follower engagement, and coupon campaigns that drive Instagram/Facebook growth, with Shopify connected only as a data source for catalog and order analytics. The UI and copy must not suggest that OmniConnect is a Shopify replacement, store-management tool, or full e-commerce admin.

## 2. Goals

- Replace the crowded top header with a collapsible hamburger sidebar and clearly grouped Meta-first navigation.
- Remove or hide pages that imply store/product administration beyond syncing from Shopify.
- Convert product catalog and order views to **read-only** Shopify imports used for AI/coupon context.
- Simplify the store concept in the UI to “Connect a Shopify/Meta source,” not “Create/manage stores.”
- **Permanently delete** placeholder growth modules and Shopify-admin pages that are not part of the Meta marketing workflow; do not just hide or archive them.
- Update landing, onboarding, dashboard, and empty-state copy to reflect Meta-first positioning.

## 3. Non-Goals

- Do not replace Shopify or build a customer-facing storefront.
- Do not remove the Shopify/Meta connectors or the underlying `Store`/`Product`/`Order` models.
- Do not add new integrations (TikTok, WooCommerce, etc.).
- Do not refactor the DDD module boundaries.

## 4. User Stories

- As a creator, I want the app to open with “Grow on Instagram/Facebook” so I immediately understand its purpose.
- As a Shopify merchant, I want to connect Shopify once and then see AI insights, not manage my Shopify catalog inside OmniConnect.
- As a staff member, I want a clean sidebar with only the sections relevant to Meta engagement (Inbox, Followers, Campaigns, Insights).
- As an admin, I want dead-end pages hidden or labeled as “Coming soon” so users do not report them as broken.

## 5. Domain Model

No schema changes. Existing entities are reused with read-only surface where noted:

- `Organization` — unchanged.
- `Store` — presented as a connected source; create action remains for onboarding but archive/restore/delete admin controls are removed from the UI.
- `Product` — read-only mirror from Shopify; no edit/delete in the UI.
- `Coupon` — lifecycle remains, but only for coupons generated by Meta campaigns (first-follower / DM). Generic standalone coupon management is removed from the UI.
- `Order` — read-only analytics source.

## 6. Public Contract

- Navigation metadata is a Presentation concern; no cross-module contract changes.
- `productQueries.getStoreProducts` remains public; `productRepository.update`/`delete` are kept for future but not exposed through UI server actions.
- `storeRepository.archive`/`restore`/`delete` are retained but unexported from presentation actions.

## 7. Data / Persistence

No new migrations. Soft-delete columns already exist. Only UI and action exposure change.

## 8. API / UI Surface

### Navigation (new)

Collapsible sidebar with groups:

1. **Connect**
   - Sources / Add source
   - Meta Connect
   - Shopify Connect
2. **Engage**
   - Inbox
   - Followers
   - Campaigns (first-follower)
3. **Create**
   - Post Ideas
   - Trends / Hashtags
   - Media (UGC — coming soon)
4. **Analyze**
   - Analytics
   - Competitors
5. **Settings**
   - Account
   - Team
   - Billing
   - Notifications

### Pages/routes to delete permanently

The following routes are out of the Meta-first scope or duplicate existing Meta workflows. Their files should be removed and their nav links deleted:

- `/stores/[storeId]/affiliates`
- `/stores/[storeId]/media-kit`
- `/stores/[storeId]/growth`
- `/stores/[storeId]/revenue`
- `/stores/[storeId]/projects`
- `/stores/[storeId]/daily-marketing`
- `/stores/[storeId]/engagement`
- `/stores/[storeId]/brand-deals`
- `/projects`
- `/stores/[storeId]/commerce/leads` (unwired lead scoring UI)
- `/stores/[storeId]/commerce/growth` (overlaps UGC/ambassador features outside scope)
- `/stores/[storeId]/commerce/catalog` (overlaps product sync; keep only if shoppable-media sync is real)
- `/stores/[storeId]/orders` (read-only orders widget remains in Analytics; list page is Shopify admin)
- `/stores/[storeId]/settings` archive/restore/delete forms (keep only display name / integration health)
- `/settings/rollout`, `/settings/operating-model`, `/settings/quality`, `/settings/unified-context` if present and unused

### Pages to simplify

- `/stores` → rename to “Sources” or “Connected businesses”; remove archive/restore/delete buttons.
- `/stores/[storeId]/products` → read-only list with “Sync from Shopify” and “Used for AI/coupons” helper text; remove edit/delete.
- `/stores/[storeId]/coupons` → show only campaign-generated coupons; remove generic delete/disable.
- `/stores/[storeId]/settings` → reduce to source display name and webhook health; remove archive/delete.
- `/stores/[storeId]/analytics` → keep; ensure copy says “Insights from your connected sources.”

### Components

- New `MobileSidebar` and `DesktopSidebar` replacing `TopNav`.
- `MetaFirstHero` / updated empty states on dashboard.
- Cleanup unused components that were only referenced by deleted pages.

## 9. External Integrations

No changes to Meta Graph or Shopify connector contracts. Only the call sites and copy change.

## 10. Edge Cases & Failure Modes

- User without any connected source: show source-empty state, not product-empty state.
- User with Shopify but no Meta: emphasize Meta connect before campaigns.
- Staff user: sidebar only shows Engage/Analyze; no Connect Settings except read-only.

## 11. Security & Privacy

- Removing UI actions reduces the attack surface but server-side enforcement remains via `tenantGuard`.
- Server actions that are no longer exposed in UI should be unexported from `src/modules/*/presentation/actions.ts` (or guarded behind role if needed later).

## 12. Testing Strategy

- Verify navigation renders all links and hides disabled routes for each role.
- Verify direct navigation to a hidden route returns 404 or “Coming soon” UI.
- Verify product list is read-only (no edit/delete buttons) and store actions no longer include archive/delete.

## 13. Acceptance Criteria

- [ ] Sidebar/hamburger replaces crowded top header.
- [ ] Navigation labels are Meta-first and do not read as Shopify admin.
- [ ] All placeholder/dead-end store-scoped pages are hidden or marked “Coming soon.”
- [ ] Product catalog is read-only; edit/delete buttons removed.
- [ ] Store lifecycle UI reduced to connect/rename; archive/restore/delete removed.
- [ ] Dashboard, onboarding, and empty states use Meta growth copy.
- [ ] Lint, typecheck, tests, build pass.
- [ ] `CHANGELOG.md` updated.

## 14. Open Questions

1. Should `Store` be renamed to `Source` in the UI copy only, or should the database model and API also be renamed?
2. Should the `/stores/[storeId]` detail page remain, or redirect to `/sources/[storeId]/analytics`?
3. Is “UGC collection” still a planned Meta feature, or should it be removed entirely?
4. Should coupon deletion remain available in the backend for admin support, or be fully disabled?
5. Should `commerce/catalog` be kept for Meta shoppable-media sync or deleted in favor of the product sync on `/stores/[storeId]/products`?
6. Should `commerce/leads` and `commerce/growth` be kept if they have real backend wiring, or deleted as placeholders?
